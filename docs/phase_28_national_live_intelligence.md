## 1. Executive Summary

Phase 28 delivers the production-ready **National Live Disaster Intelligence and Unified Risk Presentation Layer** for the RISK // INDIA platform. This milestone unifies all official live intelligence feeds, regional vulnerability baselines, approved empirical ML models, verified emergency resources, data freshness audits, and provider health metrics across all **28 States and 8 Union Territories** (36 administrative entities) and all **6 primary hazards**:
- `FLOOD`
- `EARTHQUAKE`
- `CYCLONE`
- `HEATWAVE`
- `LANDSLIDE`
- `SEVERE_WEATHER`

A core architectural principle established in Phase 28 is the **complete decoupling of data freshness from risk severity**. An active high-risk flood event with stale gauge telemetry remains classified as `HIGH RISK / STALE` and is **never** fraudulently converted to `LIVE`. Furthermore, upstream telemetry provider faults are fully isolated: failures or timeouts in external APIs (e.g. USGS, CWC, IMD, GSI) fall back to cached data without degrading unrelated hazards or failing the system.

## 2. Core Architectural Pillars

### 2.1 Decoupled Data Freshness Engine (`freshness_engine.py`)
Data freshness is determined strictly based on observation UTC timestamps, retrieval timestamps, cache status, and baseline indicators:

| Freshness Classification | Deterministic Criteria | System Handling |
|:---|:---|:---|
| `OFFICIAL_LIVE` | Observation age < 1 hour, direct upstream feed | Rendered with emerald live pulse indicator |
| `OFFICIAL_RECENT` | Observation age 1 hour to 24 hours | Rendered with sky-blue recent indicator |
| `CACHED` | Valid telemetry served from operational database/cache | Rendered with amber cache tag; NEVER labeled LIVE |
| `STALE` | Observation age > 24 hours | Explicit stale indicator warning; triggers background refresh |
| `REGIONAL_BASELINE` | Published government framework (NDMA, BIS, IMD normals) | Informational baseline vulnerability |
| `EMPIRICAL_ML` | ML inference generated by approved model | Purple ML indicator (Assam prototype only) |
| `UNAVAILABLE` | External feed offline and zero cache exists | Explicit degradation warning; baseline fallback |

**Inviolate Freshness Rule:** Freshness is orthogonal to severity. `CRITICAL RISK + STALE` data is displayed as `CRITICAL RISK [STALE]`.

### 2.2 Data Provenance & Auditability Engine (`provenance_engine.py`)
Every data point in the unified national presentation carries an immutable provenance record:
- `provider`: Official upstream entity (`USGS_SEISMIC`, `CWC_CENTRAL_WATER_COMMISSION`, `IMD_WEATHER`, `IMD_CYCLONE`, `IMD_HEATWAVE`, `GSI_LANDSLIDE`, `NDMA_BIS_CWC_IMD_FRAMEWORK`, `ASDMA_DISASTER_MANAGEMENT`)
- `source_type`: Origin category (`HYDROLOGICAL_GAUGE`, `SEISMIC_TELEMETRY`, `SATELLITE_NOWCAST`, `REGIONAL_VULNERABILITY_BASELINE`, etc.)
- `source_record_id`: Authoritative source identifier
- `observation_timestamp`: Original observation time in UTC
- `retrieval_timestamp`: Platform ingestion time in UTC
- `freshness`: Deterministic freshness enum value
- `fallback_status`: Upstream or fallback indication
- `data_license`: Official Open Government Data (OGD) / Public Disaster Advisory notice

### 2.3 Comprehensive Regional Baseline Engine (`regional_baseline.py`)
Provides deterministic multi-hazard vulnerability baselines across all 28 States and 8 Union Territories based on published government standards:
- **Seismic Zonation:** Bureau of Indian Standards (BIS IS 1893:2016) Zones II, III, IV, and V
- **Flood Corridors:** Central Water Commission (CWC) basin flood recurrence & river morphology
- **Cyclone Vulnerability:** NDMA / IMD coastal vulnerability index and Bay of Bengal / Arabian Sea landfall corridor frequencies
- **Landslide Susceptibility:** Geological Survey of India (GSI) National Landslide Susceptibility Mapping (NLSM)
- **Heatwave Zones:** IMD core heatwave zone (CHZ) climatological summer maxima
- **Severe Weather:** IMD regional monsoon convective squall and lightning hazard indices

### 2.4 Scientific ML Scope Guard & Explainability (`risk_explanation.py`)
The platform enforces strict scientific honesty regarding machine learning readiness:
- **Assam Basin Corridor:** `assam_flood_prototype_v1` is active, validated on 13 hydro-meteorological features across 32 audited empirical flood observations and 12 corroborated events.
- **Non-Assam Regions:** Machine learning is strictly deactivated (`empirical_ml.available = False`, `status = 'NOT_AVAILABLE'`). The API and UI transparently display:
  > *"Empirical ML prediction is not currently validated for this region. Regional baseline risk and official disaster intelligence are shown."*
- **Explainability:** Provides human-readable "Why This Risk?" rationale breaking down contributing environmental drivers without fabricating pseudo-weights.

### 2.5 Multi-Hazard Aggregation & Fault Isolation (`hazard_aggregation.py`)
- Isolates upstream provider failures using circuit breakers.
- Merges active official warnings with regional baselines.
- Calculates deterministic composite state risk score and primary hazard.
- Links verified emergency relief resources from authoritative registries (`ResourceService`).

## 3. REST API Contracts

### 3.1 `GET /api/national-risk`
Returns national disaster risk summary across all 36 administrative entities.
- Query parameters: `hazard` (e.g. `FLOOD`), `level` (e.g. `HIGH`), `status` (e.g. `OFFICIAL_LIVE_WARNING`).
- Response includes `total_administrative_entities: 36`, `states_covered: 28`, `union_territories_covered: 8`, `synthetic_records: 0`.

### 3.2 `GET /api/national-risk/{region}`
Returns normalized single-region intelligence for any state or UT (e.g. `/api/national-risk/Assam`, `/api/national-risk/Ladakh`):
- All 6 hazard profiles with scores, levels, freshness, and provenance
- Active official disaster alerts
- Regional baseline profile
- Empirical ML status (with scope guard)
- Verified emergency resources (helplines, NDRF/SDRF, relief centers)
- Upstream provider health and circuit breaker status
- Transparent explanation and limitation text
- `synthetic_records: 0`

### 3.3 `GET /api/national-risk/{region}/{hazard}`
Returns hazard-specific intelligence for a single state and hazard type (e.g. `/api/national-risk/Assam/FLOOD`). Returns 400 for unsupported hazard types.

### 3.4 `GET /api/national-risk/freshness`
Returns nationwide data freshness audit, distribution breakdown (`OFFICIAL_LIVE`, `OFFICIAL_RECENT`, `CACHED`, `STALE`, `REGIONAL_BASELINE`, `EMPIRICAL_ML`), and provider status.

### 3.5 `GET /api/national-risk/providers`
Returns health metrics, last retrieved timestamps, error diagnostics, and circuit breaker states for all upstream providers (`usgs_seismic`, `cwc_flood`, `imd_weather`, `imd_cyclone`, `imd_heatwave`, `gsi_landslide`).
